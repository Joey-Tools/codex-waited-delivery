# Waited Delivery Compatibility Retirement

## Summary

- Retire waited-delivery from active skill discovery while preserving explicit recovery tooling and fail-open behavior for stale hook registrations.

## Current State

- The compatibility skill lives at `skills/waited-delivery-compat` and requires explicit invocation.
- Byte-identical non-discoverable legacy assets remain at both the standalone release asset and historical direct-link target. The adapter is inert and fail-open. The runner opens the packaged compatibility source with `O_NOFOLLOW`, stable-reads and validates its object/access/size/content, copies those bytes to a verified owner-private `0600` snapshot, unlinks the name, and executes only that inherited descriptor through the current interpreter while preserving canonical `__file__`, argv, and process signals. A post-binding source replacement cannot change executed bytes, so active pre-rename children remain operable until they drain. Neither target has a `SKILL.md`.
- Recovery rewrites persisted child and parent prompts through descriptor-bound bridge and runner snapshots while publishing the canonical compatibility-runner path before returning continuation guidance.
- Every runner state read-modify-write operation now holds one run-level lock; state loads bind the opened file's device/inode and SHA-256 content version, and state saves compare that original version before descriptor-relative atomic replacement while distinguishing missing, replaced, content-changed, and unreadable state. Final publication also binds the named artifact back to the fsynced temporary inode and intended bytes.
- Fallback smoke execution keeps one run-directory fd and one lock-file fd, snapshots its command, state version, and stable no-follow prompt bytes with the lock held, and gives the helper only an inherited `O_RDONLY` descriptor path for an owner-private, verified, unlinked copy of those bytes. It unlocks that same run-lock fd for the hard-time/byte-bounded process-group run, closes the prompt snapshot before reacquiring the lock, and CAS-merges only the result. Output supervision is initialized before process launch, and every nonzero helper result becomes a `BLOCKED:` sample even if stdout or stderr contains `READY`. One deferred `SIGHUP`/`SIGTERM`/`SIGQUIT` transaction remains armed across the start-new-session helper, proves bounded process-group kill/drain/reap, restores the original handlers/mask, and only then redelivers the first signal; default handlers terminate and returning custom handlers resume with a nonzero blocked result. Phase and child-terminal updates remain available while a smoke is hung; lock replacement, run object/access drift, prompt-path replacement, or a concurrent smoke-state change fails closed.
- The Stop hook validates exact current-repo containment, exact `state.repo_root`, no-symlink path components, regular state/prompt files, current-user ownership, and stable run object/access identity before and after automatic prompt refresh. Exact owned legacy mode `0755` is tightened through the pinned directory fd to `0700` with object and owner/group revalidation; every other non-`0700` policy fails closed. It keeps the original run fd open and, before any refresh process starts, stable-reads both bridge and runner sources, copies the bound bytes into an owner-only `0700` temporary directory as `0600` files, opens and verifies them as `O_RDONLY`, unlinks both names, and revalidates each source object's identity, access policy, size, and digest. It executes only the inherited snapshot FDs through Python `-I -B -S` with Python injection variables removed and no source/sibling fallback. The outer launch now starts a new session with a seven-second hard deadline, a `256 KiB` combined capture ceiling, and bounded whole-process-group kill/drain/reap; one deferred `SIGHUP`/`SIGTERM`/`SIGQUIT` transaction keeps the snapshots open through cleanup and redelivers only after live descendants are gone. On Linux, a bounded `/proc` scan accepts a proven zombie-only group while unreadable or ambiguous evidence remains live and fails closed. The bridge forwards both FDs with the same isolation; under the run lock, the runner performs the final dual-snapshot revalidation immediately before the first prompt/state write. Refresh schema `2` binds both exact executed snapshot versions, both read-only access modes, isolated execution, and the prompt versions. Permanent source replacement, access-policy drift, or content drift fails before process or run-file writes; a launch-window A→B→A change cannot execute the intermediate object. The adapter still rereads each named prompt along the pinned run fd, binding object/access/size plus two bounded byte reads and SHA-256 digests. Metadata-only timestamp churn remains benign, while external, access-changed, content-changed, symlink-backed, or regular-file/directory replacement run records fail closed before a prompt path is rendered.
- The repo-local hook index now uses a descriptor-bound `index.lock` transaction that covers load, selection, bridge/state work, mutation, and atomic commit for prompt, Stop, prepare, attach, finish, and reconcile commands. Its adapter directory is created as exact `0700` even under an owner-bit-masking umask; newly committed index snapshots and the no-follow regular lock are `0600`. Stable bounded reads bind object identity, owner/access policy, size, and content, while commits use a verified sibling temporary file, file and directory durability, and atomic replacement. This protects against symlink escape/overwrite, umask disclosure of `last_prompt`, partial JSON visibility, and stale concurrent read-modify-write loss; the deliberate commit-time inode change is not treated as mutation. After a nonterminal Stop path has successfully rendered a blocking prompt, a later index commit/revalidation failure is logged but cannot downgrade its exit status from `2` to fail-open `0`.
- Dirty-file discovery now consumes `git status --porcelain=v1 -z` records and retains both rename/copy path fields before filtering `.codex-tmp`, so moving tracked implementation into an ignored destination still leaves the tracked source in the frozen change set.
- Linux process-group checks in both test support and the Stop-hook refresh path distinguish a proven zombie-only group from a live descendant with bounded byte-oriented `/proc` evidence; non-UTF-8 process names remain parseable, while unreadable, iterator-failed, or ambiguous evidence remains live. Output selectors are initialized before any pipe or process group exists, so selector resource exhaustion cannot leak a launched process or file descriptors.
