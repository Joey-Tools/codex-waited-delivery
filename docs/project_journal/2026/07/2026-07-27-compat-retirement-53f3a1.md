# Waited Delivery Compatibility Retirement

## Summary

- Retire waited-delivery from active skill discovery while preserving explicit recovery tooling and fail-open behavior for stale hook registrations.

## Current State

- The compatibility skill lives at `skills/waited-delivery-compat` and requires explicit invocation.
- Byte-identical non-discoverable legacy assets remain at both the standalone release asset and historical direct-link target. The adapter is inert and fail-open. The runner opens the packaged compatibility source with `O_NOFOLLOW | O_NONBLOCK`, rejects a FIFO or other non-regular source after `fstat` without waiting for another endpoint, stable-reads and validates a regular source's object/access/size/content, forks a one-shot anonymous-pipe writer, and replaces itself with a fixed Python `-I -B -S -c` bootstrap. The bootstrap verifies the exact size, EOF, and SHA-256, reaps the writer, preserves canonical `__file__`, argv, PID, and process-signal semantics, and compiles the bytes in memory. No regular-file source snapshot exists. A post-binding source replacement or mutation through a pre-held writable FD or hard link cannot change executed bytes, so active pre-rename children remain operable until they drain. Neither target has a `SKILL.md`.
- Recovery rewrites persisted child and parent prompts through separately framed anonymous-pipe bridge and runner source delivery while publishing the canonical compatibility-runner path before returning continuation guidance.
- Every runner state read-modify-write operation now holds one run-level lock; state loads bind the opened file's device/inode and SHA-256 content version, and state saves compare that original version before descriptor-relative atomic replacement while distinguishing missing, replaced, content-changed, and unreadable state. Final publication also binds the named artifact back to the fsynced temporary inode and intended bytes. State is fully serialized before publication; the hard ceiling accepts a fully serialized terminal state of exactly `4 MiB`, while any current state or required terminal projection above the ceiling is rejected before temporary-name allocation, file creation, or replacement so the previous state remains unchanged and recoverable. Every nonterminal save now reserves the maximum encoded child ID, child-start timestamp, bounded late-bound parent metadata, interrupted-child transition, decision-point closure of open phases, mandatory terminal timestamps, and the derived overall status. Child IDs are capped at `1024` UTF-8 bytes and `6146` JSON-value bytes. The old terminal-only exact limit is rejected before run creation; the new worst-case exact limit remains sufficient for prepare, maximum attachment, finish, and finalize. Exact `1025`-byte child IDs and `4097`-byte parent metadata are rejected before opening state, leaving its object/version unchanged. Finish, finalize, and parent reconciliation build a timestamp-stable candidate and pass the exact encoded-size check before publishing summary or terminal artifacts, so a `+1`-byte terminal transition leaves both old state and any existing summary recoverable for retry. Prompt refresh binds the canonical child/parent prompt paths into its candidate and performs the same check before replacing either prompt. Initial `prepare` now also builds its full schema `5` candidate, terminal projection, and every UTF-8 prompt/contract/smoke artifact before opening or creating the run path. Schema `5` records SHA-256 plus UTF-8/JSON lengths only for oversized bounded text loaded from schemas `1` through `4`; an unchanged `1025`-byte legacy child ID or `4097`-byte legacy parent field can still pass phase/save/finish/finalize, while any new or changed oversized value fails closed. Explicit empty IDs, filesystem-overlong explicit or generated IDs, unencodable artifact text, and `+1`-byte terminal projections therefore leave both the prospective run and missing/unavailable parent path untouched with no stdout; exact capacity proceeds to creation and reports a real unavailable parent only after preflight. Once creation starts, `.codex-tmp`, the runs root, and the exact run entry are each opened without following links, identity-revalidated, and parent-directory-fsynced before any artifact is published, so successful preparation does not outrun run-tree name durability.
- Ordinary runner reopen now descriptor-walks repository-side parents and requires current-user ownership, no group/other write, and no Darwin extended or Linux POSIX ACL on the parents, run, state, child/parent prompts, smoke prompt, and run lock. A run must be `0700`; only a current-user exact legacy `0755` run can be tightened through its already-open descriptor, with the object and access policy revalidated before any artifact read. Fallback smoke execution keeps one run-directory fd and one lock-file fd and binds its command, state version, both child/parent prompt versions, and stable no-follow smoke-prompt bytes with the lock held. Immediately before `Popen` it revalidates the parent/run policy, lock, state, and prompt versions. It creates an anonymous pipe, gives the helper only the inherited read-descriptor path, and keeps the writer parent-private. Immediately after launch it closes the parent's read copy so that copy cannot hide a helper-side early close. It unlocks that same run-lock fd while one selector writes the bounded prompt, closes the writer for EOF, captures stdout/stderr, and performs hard-time/byte-bounded process-group supervision. A reader close detected before complete delivery is terminal `126`; no regular-file prompt snapshot exists. Complete pipe delivery proves only that the kernel accepted all bound bytes while a reader existed, not that the helper semantically consumed them. Both pipe ends close before the same lock descriptor is reacquired and only the smoke result is CAS-merged. Every nonzero helper result becomes a `BLOCKED:` sample even if stdout or stderr contains `READY`. One deferred `SIGHUP`/`SIGTERM`/`SIGQUIT` transaction remains armed across delivery and the start-new-session helper, proves bounded process-group kill/drain/reap, restores the original handlers/mask, and only then redelivers the first signal; default handlers terminate and returning custom handlers resume with a nonzero blocked result. Phase and child-terminal updates remain available while a smoke is hung; lock replacement, run object/access drift, prompt-path replacement, or a concurrent smoke-state change fails closed.
- The adapter now applies one descriptor-bound access-policy contract across the repository root, `.codex-tmp`, adapter directory, index, lock, preparation lease, runs root, run, state/prompts, and bridge/runner source parents and files. Each must be current-user-owned, reject group/other write, and carry no Darwin extended or Linux POSIX ACL; held descriptors revalidate the selected identity and policy at the corresponding read, commit, or launch boundary. Exact owned legacy run mode `0755` is tightened through the pinned directory fd to `0700` with object, owner/group, mode, and ACL revalidation; every other non-`0700` run policy fails closed.
- Every adapter-to-bridge operation—prepare, parent binding, child attachment, child finish, parent reconciliation, and prompt refresh—stable-binds both source objects and exact bytes before launch. A fixed Python `-I -B -S -c` bootstrap validates one bounded two-source frame and compiles the bridge in memory; that bridge sends the already bound runner bytes through a second validated frame to another isolated bootstrap. No adapter-driven command path-executes or reopens either source, and no regular-file source snapshot or inherited source FD exists. Prompt refresh retains its schema `3` source-provenance and transport receipt. Stop/reconcile state loads accept runner schemas `1` through `5` only and reject every future schema. `reconcile-active-run` now pre-binds the run identity, the no-follow owner-private `.state.lock` object without holding it, initial state receipt, indexed run ID, parent session, preparation transaction, attached child ID, and requested terminal status. It requires runner JSON to return the exact previous and published state versions plus the same run identity. After the bridge releases its lock, the adapter acquires that same pinned lock object, matches the receipts and semantics to post-call and final descriptor reads, and holds the lock through actual descriptor-bound atomic index publication. The atomic publisher invokes the full named run/lock/state guard immediately before `os.replace` and after durable index readback. Once replacement is attempted, any exception descriptor-classifies the visible index as the exact previous snapshot, exact prepared publication, or neither; a published snapshot restores the previous bytes or absence and verifies the recovery file's complete device/inode/uid/gid/mode/size/digest version. Directory-fsync, published-readback, post-publication-guard, and transaction-final directory/lock-revalidation failures all use that path. An unproved state reports `manual_recovery_required=true` with previous/published digest evidence and no success. This guarantee ends at transaction-final revalidation, before later descriptor-close or unlock cleanup. The index clears only for that locked unchanged terminal object/version.
- Runner fallback smoke, adapter bridge processes, and subprocess test support now attest native `sigaction(SIGCHLD)` before selector, pipe, or `Popen`: Python/native handlers must be default, `SA_NOCLDWAIT` must be absent, Linux must provide `waitid`, and Darwin must provide `kqueue` `NOTE_EXIT`. The reviewed finalizer contract requires CPython. Darwin uses its public layout; Linux is fail-closed to reviewed LP64 glibc `x86_64-linux-gnu` and `aarch64-linux-gnu` layouts, so another Python implementation, musl, unknown ABI, unsupported platform, native-query failure, or missing capability stops before libc process operations or launch. Because `SIGCHLD` is process-global, cooperating code must not mutate it during the transaction; the runtime re-attests immediately before launch, after observer binding, before Darwin's PID-list call and every individual `proc_pidinfo`, before every numeric Linux `/proc/<pid>/stat` read, and before every other status observation, numeric PID/PGID signal or probe, and reap. A transient A→B→A fence change stops the current scan at B and cannot resume after A is restored. Once post-launch identity loss is observed, the transaction permanently skips group operations, closes its pipes, performs no direct-child wait, poll, or reap because the numeric PID may already have been reused, and treats status as unavailable. Before any reference can be released, it verifies the impossible POSIX return-code sentinel `sys.maxsize` as the core numeric-identity barrier. Clearing CPython's `_child_created` finalizer gate and retaining the strong `Popen` object as recovery evidence are separately retried and reported, rather than assumed. A Darwin `kqueue` remains locally owned until observer binding succeeds, and every constructor failure closes it without masking the primary exception. While the fence remains valid, Darwin treats `proc_listpgrppids` output as a PID count, calls `proc_pidinfo` with flavor `3` and argument `1`, clears/reads `errno`, recognizes status `5` as zombie, and classifies full-buffer, zero/short, mismatched, expired, or errored evidence as unknown. An observer-bind failure with a valid fence uses one absolute deadline for `SIGKILL`, nonblocking pipe drain, whole-group proof, and bounded reap; incomplete cleanup retains the unreaped leader, while a successful reap terminates all later signal/probe activity.
- Darwin's exact `kqueue`-attested, still-unreaped known leader is already identity-bound as exited, so after a full size/PID/PGID match its temporarily stale non-`5` `libproc` status is treated as exited. This narrow exception never applies to an unattested PID or same-group descendant; a zero-size/`ESRCH`, short, mismatched, failed, or other unknown result remains fail-closed.
- Every exception from an after-spawn native re-attestation, including `KeyboardInterrupt` and other `BaseException` subclasses, now becomes permanent identity loss with its original cause. Python 3.9 and current-Python CI exercise the real CPython finalizer contract. A sentinel-verification failure falls back to a deliberate permanent `Py_IncRef` leak so interpreter teardown cannot invoke an armed `Popen.__del__`; two failed pin attempts fail-stop through `_exit(70)` without Python finalization. Recovery-list retention is retried and reported independently from numeric-identity safety.
- The protected transport property begins after source or prompt bytes are stable-bound: a same-UID filesystem attacker, including one with a pre-held writable descriptor or hard link to the original regular file, cannot alter the bytes later compiled or offered to the helper. Prompt-pipe success attests complete delivery only, not semantic consumption. The contract does not claim protection against `ptrace`, debugger or process-memory injection, or arbitrary code already executing in the trusted process.
- The repo-local hook index uses schema `3` and descriptor-bound `index.lock` transactions for each load/mutation/atomic commit. Its adapter directory is created as exact `0700` even under an owner-bit-masking umask; newly committed index snapshots, the no-follow regular lock, and preparation leases are `0600`. Adapter directory name entries are identity-revalidated and parent-directory-fsynced. Stable bounded reads bind object identity, owner/access policy, size, and content, while commits use a verified sibling temporary file, file and directory durability, and atomic replacement. Schema-v2 readers reject schema `3` before mutation, so they cannot reinterpret `cleanup_pending` plus `run_dir` as active; schema `3` can still decode and recover existing v2 reservations. `prepare-active-run` uses short index transactions around bridge work. Phase one first refuses to replace an existing association unless its direct repo-local path, access policy, state, prompts, repo root, and terminal state pass descriptor-bound no-follow validation; it then preflights a worst-case bounded recovery reason, creates a stable UUID/run/path/lease reservation, commits `preparing`, and releases `index.lock` before bridge launch. The locked preparation-lease descriptor is inherited by bridge and runner, so a crash-time doctor cannot treat temporary path absence as quiescence while a cooperating descendant may still create or write the run. Runner state schema `5` writes, schema `4` recovery compatibility, the bridge receipt, and the activation CAS all bind the same preparation UUID, exact run ID/path, repo root, and parent session. After a bridge failure, the adapter retires its original inherited lease reference exactly once and independently reopens and nonblocking-locks the lease before any run-entry read; a surviving descendant or ambiguous close therefore leaves `recovery_required` and cannot create an unindexed run after false absence. A descriptor-proven quiescent absence CAS-enters `cleanup_pending` with the full reservation, descriptor-unlinks the exact lease and fsyncs its adapter parent, and only then exact-record-CAS-publishes `cleanup_complete` while retaining the preparation/run/lease identity. If replacement, final fsync, readback, or post-commit revalidation fails after publication, the transaction now restores the exact prior `cleanup_pending` snapshot when that recovery can be proved; retry then performs the same final CAS from disk. A verified tombstone may be superseded by a new exact reservation; a retry bearing the old preparation ID then fails closed and cannot clear the new record. A present/partial run, wrong receipt, state attestation mismatch, index drift, or other unproved transition remains fenced and emits no stdout. `recover-active-run doctor|resume|clear-absent` reports busy, pending, or completed cleanup states, promotes only a complete same-transaction run, and finalizes only through the ordered full-identity cleanup protocol; it never follows a foreign returned path or recursively deletes a run. UserPromptSubmit preserves preparation and tombstone fields, Stop treats a completed tombstone as no active run, and attach/finish/reconcile require `active`. After a nonterminal Stop path has successfully rendered a blocking prompt, a later index commit/revalidation failure is logged but cannot downgrade its exit status from `2` to fail-open `0`.
- Dirty-file discovery now consumes `git status --porcelain=v1 -z` as binary NUL-framed records and retains both rename/copy path fields before filtering `.codex-tmp`, so moving tracked implementation into an ignored destination still leaves the tracked source in the frozen change set. Filesystem `surrogateescape` decoding occurs only after framing, preserving non-UTF-8 filename bytes and embedded carriage-return/line-feed semantics in JSON state. Both human-readable consumers share one escape grammar that preserves short ordinary printable Unicode while escaping invalid bytes, backslashes, Markdown backticks, edge spaces, and every Unicode control/format/line/paragraph separator. Per-path output is capped at `512` UTF-8 bytes. An input cannot forge the reserved `⟦truncated;...⟧` token because its delimiters are escaped in path content. That token binds identity kind, byte length, and SHA-256: exact `os.fsencode()` bytes for filesystem-encodable paths, or explicitly labeled, stable `utf8-surrogatepass` bytes for non-surrogateescape surrogates and other filesystem-codec failures.
- Linux process-group membership checks in the compatibility runner, test support, and adapter paths distinguish a proven zombie-only group from a live descendant with bounded byte-oriented `/proc` evidence; non-UTF-8 process names remain parseable, while unreadable, iterator-failed, or ambiguous evidence remains live. Output selectors are initialized before any pipe or process group exists, so selector resource exhaustion cannot leak a launched process or file descriptors.
