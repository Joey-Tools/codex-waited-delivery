# Waited Delivery Compatibility Retirement

## Summary

- Retire waited-delivery from active skill discovery while preserving explicit recovery tooling and fail-open behavior for stale hook registrations.

## Current State

- The compatibility skill lives at `skills/waited-delivery-compat` and requires explicit invocation.
- Byte-identical non-discoverable legacy assets remain at both the standalone release asset and historical direct-link target. The adapter is inert and fail-open. The runner opens the packaged compatibility source with `O_NOFOLLOW | O_NONBLOCK`, rejects a FIFO or other non-regular source after `fstat` without waiting for another endpoint, stable-reads and validates a regular source's object/access/size/content, forks a one-shot anonymous-pipe writer, and replaces itself with a fixed Python `-I -B -S -c` bootstrap. The bootstrap verifies the exact size, EOF, and SHA-256, reaps the writer, preserves canonical `__file__`, argv, PID, and process-signal semantics, and compiles the bytes in memory. No regular-file source snapshot exists. A post-binding source replacement or mutation through a pre-held writable FD or hard link cannot change executed bytes, so active pre-rename children remain operable until they drain. Neither target has a `SKILL.md`.
- Recovery rewrites persisted child and parent prompts through separately framed anonymous-pipe bridge and runner source delivery while publishing the canonical compatibility-runner path before returning continuation guidance.
- Every runner state read-modify-write operation now holds one run-level lock; state loads bind the opened file's device/inode and SHA-256 content version, and state saves compare that original version before descriptor-relative atomic replacement while distinguishing missing, replaced, content-changed, and unreadable state. Final publication also binds the named artifact back to the fsynced temporary inode and intended bytes. State is fully serialized before publication, exactly `4 MiB` is accepted, and any larger encoded payload is rejected before temporary-name allocation, file creation, or replacement so the previous state remains unchanged and recoverable.
- Fallback smoke execution keeps one run-directory fd and one lock-file fd and binds its command, state version, and stable no-follow prompt bytes with the lock held. It creates an anonymous pipe, gives the helper only the inherited read-descriptor path, and keeps the writer parent-private. Immediately after launch it closes the parent's read copy so that copy cannot hide a helper-side early close. It unlocks that same run-lock fd while one selector writes the bounded prompt, closes the writer for EOF, captures stdout/stderr, and performs hard-time/byte-bounded process-group supervision. A reader close detected before complete delivery is terminal `126`; no regular-file prompt snapshot exists. Complete pipe delivery proves only that the kernel accepted all bound bytes while a reader existed, not that the helper semantically consumed them. Both pipe ends close before the same lock descriptor is reacquired and only the smoke result is CAS-merged. Every nonzero helper result becomes a `BLOCKED:` sample even if stdout or stderr contains `READY`. One deferred `SIGHUP`/`SIGTERM`/`SIGQUIT` transaction remains armed across delivery and the start-new-session helper, proves bounded process-group kill/drain/reap, restores the original handlers/mask, and only then redelivers the first signal; default handlers terminate and returning custom handlers resume with a nonzero blocked result. Phase and child-terminal updates remain available while a smoke is hung; lock replacement, run object/access drift, prompt-path replacement, or a concurrent smoke-state change fails closed.
- The Stop hook validates exact current-repo containment, exact `state.repo_root`, no-symlink path components, regular state/prompt files, current-user ownership, and stable run object/access identity before and after automatic prompt refresh. Exact owned legacy mode `0755` is tightened through the pinned directory fd to `0700` with object and owner/group revalidation; every other non-`0700` policy fails closed. It keeps the original run fd open and, before any refresh process starts, stable-reads both bridge and runner sources, binds object/access/size/content versions, and revalidates them before launch. It frames the bound bytes with magic, bounded exact lengths, and SHA-256 digests and sends them through anonymous stdin to a fixed Python `-I -B -S -c` bootstrap with Python injection variables removed. That bootstrap requires EOF and compiles the bridge in memory; the bridge applies an independent framed anonymous-pipe bootstrap to the runner. No regular-file source snapshot or inherited source FD exists. The outer launch starts a new session with a seven-second hard deadline, a `256 KiB` combined capture ceiling, and bounded whole-process-group kill/drain/reap; its selector services input and output together, classifies early input rejection or incomplete delivery as terminal `126`, closes the writer before cleanup, and cannot accept success before the full frame. One deferred `SIGHUP`/`SIGTERM`/`SIGQUIT` transaction redelivers only after live descendants are gone. On Linux, a bounded `/proc` scan accepts a proven zombie-only group while unreadable or ambiguous evidence remains live and fails closed. Under the run lock, the runner revalidates its injected bytes immediately before the first prompt/state write. Refresh schema `3` binds both exact source-provenance versions, both `anonymous-pipe-memory` transports, non-reopenability, canonical compile filenames, isolated execution, and the prompt versions. Permanent source replacement, access-policy drift, or content drift fails before process or run-file writes; a launch-window A→B→A change after stable binding cannot execute the intermediate object. The adapter still rereads each named prompt along the pinned run fd, binding object/access/size plus two bounded byte reads and SHA-256 digests. Metadata-only timestamp churn remains benign, while external, access-changed, content-changed, symlink-backed, or regular-file/directory replacement run records fail closed before a prompt path is rendered.
- The protected transport property begins after source or prompt bytes are stable-bound: a same-UID filesystem attacker, including one with a pre-held writable descriptor or hard link to the original regular file, cannot alter the bytes later compiled or offered to the helper. Prompt-pipe success attests complete delivery only, not semantic consumption. The contract does not claim protection against `ptrace`, debugger or process-memory injection, or arbitrary code already executing in the trusted process.
- The repo-local hook index now uses a descriptor-bound `index.lock` transaction that covers load, selection, bridge/state work, mutation, and atomic commit for prompt, Stop, prepare, attach, finish, and reconcile commands. Its adapter directory is created as exact `0700` even under an owner-bit-masking umask; newly committed index snapshots and the no-follow regular lock are `0600`. Stable bounded reads bind object identity, owner/access policy, size, and content, while commits use a verified sibling temporary file, file and directory durability, and atomic replacement. This protects against symlink escape/overwrite, umask disclosure of `last_prompt`, partial JSON visibility, and stale concurrent read-modify-write loss; the deliberate commit-time inode change is not treated as mutation. After a nonterminal Stop path has successfully rendered a blocking prompt, a later index commit/revalidation failure is logged but cannot downgrade its exit status from `2` to fail-open `0`.
- Dirty-file discovery now consumes `git status --porcelain=v1 -z` as binary NUL-framed records and retains both rename/copy path fields before filtering `.codex-tmp`, so moving tracked implementation into an ignored destination still leaves the tracked source in the frozen change set. Filesystem `surrogateescape` decoding occurs only after framing, preserving non-UTF-8 filename bytes and embedded carriage-return/line-feed semantics in JSON state. Both human-readable consumers share one escape grammar that preserves short ordinary printable Unicode while escaping invalid bytes, backslashes, Markdown backticks, edge spaces, and every Unicode control/format/line/paragraph separator. Per-path output is capped at `512` UTF-8 bytes. An input cannot forge the reserved `⟦truncated;...⟧` token because its delimiters are escaped in path content. That token binds identity kind, byte length, and SHA-256: exact `os.fsencode()` bytes for filesystem-encodable paths, or explicitly labeled, stable `utf8-surrogatepass` bytes for non-surrogateescape surrogates and other filesystem-codec failures.
- Linux process-group checks in the compatibility runner, test support, and the Stop-hook refresh path distinguish a proven zombie-only group from a live descendant with bounded byte-oriented `/proc` evidence; non-UTF-8 process names remain parseable, while unreadable, iterator-failed, or ambiguous evidence remains live. Output selectors are initialized before any pipe or process group exists, so selector resource exhaustion cannot leak a launched process or file descriptors.
